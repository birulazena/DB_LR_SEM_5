# Функциональные требования к системе

## 1. Аутентификация и безопасность
* **FR-1.1. Аутентификация:** Доступ пользователей по `email` и `password_hash`.
* **FR-1.2. Проверка статуса:** Запрет входа при `is_active = false` или `is_deleted = true`.

## 2. Управление пользователями и профилями (CRUD & Soft Delete)
* **FR-2.1. Создание (Create):** При регистрации пользователя создается учетная запись `users` и связанная 1:1 сущность персональных данных `user_profiles`.
* **FR-2.2. Чтение (Read):** Получение данных профиля по идентификатору, фильтрация пользователей по роли и статусу активности (`WHERE is_deleted = false`).
* **FR-2.3. Обновление (Update):** Редактирование персональных данных профиля (имя, фамилия, контактный номер телефона).
* **FR-2.4. Мягкое удаление (Delete):** Метод удаления пользователя переключает `is_deleted = true`. Физическое удаление запрещено для гарантии сохранности журнала аудита.

## 3. Ролевая модель на основе разрешений (RBAC)
* **FR-3.1. Структура прав:** Права доступа задаются через сущность `permissions` (например, `orders:create`, `shipments:drive`).
* **FR-3.2. Роли-контейнеры:** Сущность `roles` объединяет набор разрешений (`role_permissions`).
* **FR-3.3. Назначение пользователю:** Пользователю назначаются одна или несколько ролей (`user_roles`).
* **FR-3.4. Авторизация в API:** Spring Boot проверяет доступ к эндпоинтам по наличию конкретного разрешения.

## 4. Журнал аудита действий (Audit Logging)
* **FR-4.1. Фиксация бизнес-операций:** Запись в лог при смене статусов заказов, формировании рейсов и мягком удалении сущностей.
* **FR-4.2. Ответственный субъект:** У каждой записи аудита обязательно присутствует `user_id` автора действия (`NOT NULL`).
* **FR-4.3. Описание операции:** Текстовая фиксация сути изменения в поле `details` (без избыточных сетевых метаданных).

## 5. Управление перевозками и грузами
* **FR-5.1. Оформление заказа:** Клиент создает заказ с указанием складов отправления и назначения.
* **FR-5.2. Спецификация груза:** В заказ включаются грузовые места (`cargo_items`) с весогабаритными параметрами и количеством.
* **FR-5.3. Консолидация в рейс (Shipment):** Несколько заказов назначаются в один рейс на конкретное авто и водителя через сущность связи `shipment_orders`.
* **FR-5.4. Завершение доставки:** Водитель отмечает разгрузку конкретного заказа в рейсе флагом `is_delivered = true`.
